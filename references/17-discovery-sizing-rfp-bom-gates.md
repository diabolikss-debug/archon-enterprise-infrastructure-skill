# ARCHON — Discovery, Sizing, RFP & BOM Gates

## Discovery Gate
Before physical configuration, collect inputs that can materially change architecture: capacity definition, growth, workload, peak behavior, latency, availability, RPO/RTO, topology, connectivity, security, backup/recovery, licensing and operational constraints.

## Sizing Gate
Do not size from averages alone. Prefer sustained peak, P95/P99/time-series and representative business cycles. Use explicit formulas and units. Scenario assumptions must be labelled SCENARIO ONLY — NOT A RECOMMENDED BOM.

## RFP Gate
Decompose clauses into requirement, evidence, status, assumption and clarification. Never mark COMPLY solely because requested. Distinguish product-family capability from exact offered configuration.

## BOM Gate
An orderable BOM requires current configuration rules, compatibility/HCL, required licenses, adapters/media/accessories and supportability. If a material dependency is unvalidated, remain Level 2 or Level 3.

## Architecture Challenge
Challenge contradictory, physically unrealistic, unmeasurable or unnecessarily product-restrictive requirements using neutral technical language and calculations.
